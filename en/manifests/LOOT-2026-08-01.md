**Важно из полевых заметок:** релиз не публикует checksum-файл, целостность
проверяется только ручным сравнением SHA-256. Найден баг: при отсутствии
`line-height` в HTML движок накладывает строки друг на друга в скриншотах —
**скриншоты нельзя принимать как доказательство вёрстки без визуальной проверки**.

Паттерн установки совпал с шапкой этого манифеста: скиллы репозитория кладутся
в `en/skills/<owner>-<repo>/<skill>/`.

## Дополнение 4 (гримуар как источник истины для клонирования хоста)

Аудит показал: `install-self.sh` **не обновлял** уже установленные скиллы
(`cp -rn` пропускает существующее), **терял 12 скиллов** при разворачивании
дерева в плоский вид, **висел** на `git clone` при Tor-прокси в env и вызывал
несуществующую команду `hermes skills`. Проверено прогонами на чистом HOME.

| Файл | Назначение |
|------|------------|
| `en/scripts/install-v2.sh` | Установщик v2: обновление по контенту, сохранение структуры `<категория>/<скилл>`, отчёт о коллизиях, `env -u *proxy`, детекция drift, exit 3 при расхождении |
| `en/scripts/verify-grimoire.sh` | CI-проверка: изолированная установка + сверка количества, SHA-256 и frontmatter. Exit 0 = хост воспроизводим |
| `en/scripts/selftest-grimoire.sh` | 5 мутаций, доказывающих, что проверка не пустая (удаление скилла, битый frontmatter, устаревшая копия на хосте, потери при flatten) |
| `en/docs/HOST-REQUIREMENTS.md` | Что нужно хосту помимо скиллов: rsync, moli, node; чего гримуар сознательно НЕ хранит (секреты, config.yaml, memories) |

Результат: **895 = 895**, ни одного потерянного скилла (было 883 из 895).
Все 895 совпадают с гримуаром байт-в-байт.

**Убрано из git (1210 файлов, ~28 МБ):** `en/skills-export/` и
`ru/skills-export/` — побайтово идентичные устаревшие снимки `~/.hermes/skills`
(86 скиллов против 157 активных), плюс 12 `.curator_backups/*.tar.gz`.
Файлы остались на диске, удалены только из индекса; `.gitignore` защищает от
возврата. Источник истины — `en/skills/`, он не тронут.

⚠️ `install-self.sh` оставлен на месте для обратной совместимости — новые
хосты должны использовать `install-v2.sh`.
